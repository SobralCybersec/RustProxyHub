# Full Refactor — Idiomatic Rust Architecture

State machine for the refactor loop. **One phase per iteration.** Never batch phases.

## Standing rules (apply in every phase, never as their own pass)

- Prefer composition over inheritance-like trait-object soup.
- Prefer immutable bindings (`let`); introduce `mut` only when genuinely needed.
- No `unwrap()`/`expect()` outside `#[cfg(test)]` and throwaway prototypes — use `?`, `anyhow::Context`, or an `expect("reason")` that states an invariant.
- One responsibility per module. Split files that outgrow it.
- Comments: **one precise `/* ... */` per logic block**, placed on the line it explains. No narration of what the code obviously does. Example: `/* retry with backoff until the bridge answers */`.
- Every phase ends GREEN: `pnpm verify` passes. **Never run `git commit`, `git push`, or `git reset` — only LO commits and pushes.** Leave the phase staged and green for his review.

## Loop protocol (read this each iteration)

1. Open this file, find the **first unchecked** `[ ]` phase.
2. Do **only** that phase. If it's too big for one clean pass, do the smallest shippable slice and leave the box unchecked with a `— partial: <note>`.
3. Run `pnpm verify` (or the phase-relevant subset). If red, fix before advancing. Never advance red.
4. Check the box, append a one-line note to the progress log. Then **auto-advance to the next phase** — schedule the next iteration. Never `git commit`/`push`/`reset`; changes accumulate uncommitted for LO to commit and push whenever he wants.
5. When every **loop-doable** box (phases 0–12) is checked → write `docs/reference/refactor-summary.md` and **close the loop** (`ScheduleWakeup stop:true`). Phase 13 is LO/CI-gated: the loop never self-checks it — it stops and hands off. Skip any phase already blocked on LO (never fake a manual smoke test or a CI-green claim).
